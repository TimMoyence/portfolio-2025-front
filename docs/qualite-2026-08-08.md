## 1. sonarjs — la dette n etait pas dans le comptage

Le chiffre de 128 violations ne mesurait pas ce qu il semblait mesurer. `npm run lint`
n en voyait aucune : **15 regles `sonarjs` etaient explicitement desactivees** dans
`eslint.config.js`, avec un commentaire expliquant que les laisser en `error` casserait
`ci:check` et `pre-push:check`. Les 128 violations n etaient visibles que via une
seconde configuration, `eslint.quality.config.js`, qui les emettait en `warn` — donc
avec un code de sortie 0. Le gate ne bloquait rien.

Deux angles morts s ajoutaient a cela :

- `eslint.quality.config.js` limitait sonarjs a `src/**/*.ts` : ni `e2e/`, ni `scripts/`
  n etaient couverts ;
- `e2e/**` figurait dans les `ignores` globaux d `eslint.config.js` : ce dossier n etait
  **linte par aucune regle**. L ouvrir a fait apparaitre des `no-fixed-wait-in-tests`
  (attentes en duree fixe dans les specs Playwright, instables par construction) et des
  `no-os-command-from-path` dans `scripts/`.

Etat actuel :

- les 15 desactivations sont supprimees, `sonarjs/recommended` est integralement en
  `error` ;
- le perimetre couvre `src/`, `e2e/` et `scripts/` ;
- `--max-warnings=0` est pose sur `lint` : une directive `eslint-disable` devenue
  inutile echoue au meme titre qu une violation, ce qui empeche de reintroduire une
  regle desactivee sans que la CI le voie ;
- `eslint.quality.config.js` et le script `lint:quality` sont **supprimes** : ils
  n existaient que pour mesurer les regles neutralisees, il n y en a plus.

Les desactivations restantes sont ciblees a la ligne et justifiees sur place, avec un
fait verifiable (fixtures de test, contrainte d environnement).

## 2. jscpd — duplication

Le SCSS est passe de **6,49 % a 0,00 %** : dix partials de mixins partages ont ete
extraits dans `src/app/styles-shared/`, puis consommes par 23 fichiers de composants.
Chaque fichier touche a ete verifie par comparaison du **CSS compile normalise** avant
et apres — 32 fichiers, 32 identiques.

Le markup est passe de 6,85 % a 3,10 % par extraction de composants partages.

**Regle posee : on n extrait pas un bloc de markup porteur de marqueurs `i18n`.** Le
residuel de 3,10 % est constitue de ces blocs. Ce n est pas une limite technique subie
mais un arbitrage : deplacer un bloc `i18n` sans identifiant explicite change son
identifiant de message et orpheline sa traduction (voir section 5). Le gain de
duplication ne vaut pas le risque sur les deux locales.

## 5. Internationalisation — invariant a preserver

Deplacer un bloc `i18n` sans identifiant explicite change son identifiant de message et
orpheline sa traduction. Le controle **ne peut pas** se faire par `git diff` sur
`src/locale/` : chaque unite embarque un `<context context-type="linenumber">`, et le
retrait des 484 commentaires a decale tout le fichier. Un tel diff est du bruit a
100 %.

Le controle valable est la comparaison des **ensembles d identifiants** :

```bash
grep -oE '<trans-unit id="[^"]+"' src/locale/messages.xlf   # source, XLIFF 1.2
grep -oE '<unit id="[^"]+"'       src/locale/messages.en.xlf # traduction, XLIFF 2.0
```

Les deux fichiers ne sont pas au meme format XLIFF : un comptage naif de `trans-unit`
sur le fichier anglais renvoie 0.

Etat : **1617 identifiants source, 1617 traduits, 0 sans traduction**. Les 21
identifiants disparus correspondent a `HEATMAP_DAY_LABELS` et `TREND_DAY_LABELS`, deux
constantes qui etaient declarees et **utilisees nulle part** — leurs libelles n etaient
donc jamais rendus. Les 21 unites traduites devenues orphelines ont ete retirees de
`messages.en.xlf`.

## Ce que la CI verifie desormais

Le job `quality-gate` de `.github/workflows/ci.yml` enchaine, dans l ordre :
`lint` (ESLint + sonarjs), `format:check`, `typecheck`, `quality:dup`,
`quality:dup:tests`, `quality:knip`, `test:guards`, `guard:comments`, la couverture,
puis le build.

`ci:check` et `pre-push:check` enchainent la meme sequence en local.

## Perimetre du garde de commentaires

`scripts/lib/comment-scope.mjs` limite l inspection aux extensions source, style et
markup, sous `src/`, `e2e/`, `scripts/` et a la racine du depot. Les fichiers `.md`,
`.json` et `.yml` — dont les workflows GitHub — sont hors perimetre : leurs
commentaires ne sont pas comptes.
